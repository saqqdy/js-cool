# js-cool 6.2.0 Chain Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship js-cool 6.2.0 — a `chain` module (lodash-style eager chained array operations) reusing existing js-cool array functions + native `Array.prototype` methods, plus an additive `./chain` subpath export.

**Architecture:** Eager evaluation — each fluent method computes a new array and replaces the internal `_value`; `.value()` returns a defensive copy. Single `Chain<T>` class + `chain<T>()` factory; constructor is private (entry only via `chain()`). No generators / `for...of` / `Symbol.iterator` (IE11-clean).

**Tech Stack:** TypeScript 5.9, Rolldown 1.0-rc, Vitest 3.2 (globals + happy-dom), api-extractor, SWC (ES5 for IE11 IIFE), VitePress docs.

**Spec:** `docs/superpowers/specs/2026-08-13-v6.2.0-chain-design.md`

## Global Constraints

- Baseline 6.1.0 (assumed shipped). Target 6.2.0 (minor). No breaking API changes.
- IE11 maintained: no generator functions, no `for...of`, no `Symbol.iterator` in `src/chain.ts`; spread `[...arr]` compiles to `arr.slice()` under SWC.
- vitest `globals: true` (bare `describe`/`it`/`expect`), env `happy-dom`, setup `./test/setup.ts`. Import source directly: `from '../src/chain'`.
- Conventional-commit prefixes, imperative English. TDD per task: failing test → run (fail) → implement → run (pass) → commit.
- Main `src/index.ts` only GAINS `chain`/`Chain` exports; nothing removed.

```ts
/**
 * Eager chain over js-cool array utilities + native Array methods.
 *
 * @example
 * ```ts
 * chain([{ n: 3 }, { n: 1 }, { n: 2 }])
 *   .filter(x => x.n > 0)
 *   .sortBy('n')
 *   .take(2)
 *   .value()
 * ```
 * @since 6.2.0
 */
export class Chain<T> {
	private constructor(private _value: T[]) {}

	/**
	 * Return a defensive copy of the wrapped array (chain ends).
	 */
	value(): T[] {
		return [...this._value]
	}
}

/**
 * Create a chain wrapping a copy of `value`.
 * @since 6.2.0
 */
export function chain<T>(value: T[]): Chain<T> {
	return new Chain<T>([...value])
}

export default chain
```

- [ ] **Step 4: Add methods to `Chain<T>` in `src/chain.ts`**

```ts
	sortBy(...iteratees: SortIteratee<T>[]): Chain<T> {
		return new Chain<T>(sortBy(this._value, ...iteratees))
	}

	unique(by?: keyof T | ((v: T) => unknown)): Chain<T> {
		return new Chain<T>(unique(this._value, by))
	}

	chunk(size: number): Chain<T[]> {
		// chunk returns T[][]; element type narrows from T to T[].
		return new Chain<T[]>(chunk(this._value, size))
	}

	take(n: number): Chain<T> {
		return new Chain<T>(take(this._value, n))
	}

	drop(n: number): Chain<T> {
		return new Chain<T>(drop(this._value, n))
	}

	flatten(): Chain<T> {
		// js-cool flatten is single-level; assumes elements are arrays.
		return new Chain<T>(flatten(this._value as unknown as (T | T[])[]) as unknown as T[])
	}

	sampleSize(n: number): Chain<T> {
		return new Chain<T>(sampleSize(this._value, n))
	}
```

> **Type notes:** `chunk` honestly returns `Chain<T[]>` (elements become arrays — spec §5.1 listed `Chain<T>`, corrected here). `flatten` uses an internal cast because js-cool `flatten` is typed `(T | T[])[] → T[]`; runtime is correct (single-level flatten), typing is intentionally loose (documented).
