# js-cool 6.1.0 — Design Spec

- **Version**: 6.1.0 (minor)
- **Date**: 2026-08-12
- **Baseline**: 6.0.0 (released 2026-04-05)
- **Direction**: Stable enhancement + correctness fix. Fully backward-compatible, IE11 maintained, no breaking API changes.

## 1. Goals

1. Enhance four functional buckets via additive (optional-param / new-export) changes:
   - **A. Deep clone** — Set/Map/TypedArray/ArrayBuffer support, structuredClone fast-path, iterative rewrite to fix deep-nesting stack overflow.
   - **B. Array/object** — `groupBy` multi-field, `unique` `by` option, new `sortBy` function.
   - **C. String** — `truncate` `byWidth`/`breakEmoji`, `randomString` `preset`/`chars`.
   - **D. Date** — `formatDate` options + new tokens, export & harden `parseDate`/`parseDateWithFormat`.
2. Wire 5 additive-mirror subpath exports (`./object`, `./color`, `./string`, `./array`, `./number`).
3. Zero behavior change for existing 6.0.0 call sites; IE11 IIFE build still passes SWC→ES5.

## 2. Non-goals (deferred to 6.2+)

- Plugin mechanism, chain/lazy evaluation, schema validation (P2/P3 in `internal/upgrade-suggestions.md`).
- Removing `_compat.ts` / dropping IE11.
- Lodash-compat alias plugin.
- VS Code extension, online playground.
- Coverage hard threshold (vitest currently has none; this release keeps it that way).

## 4. Enhancements per bucket

### 4.A — Deep clone (`src/clone.ts`)

Current: recursive `_clone` with `parents`/`children` arrays for circular refs; handles Array, RegExp, Date, plain objects (preserves prototype via `Object.getPrototypeOf`/`Object.create`); uses `for...in` + `hasOwnProperty` (IE11-safe). Does NOT support Set/Map/TypedArray/ArrayBuffer; deep nesting overflows the stack.

New signature (unchanged externally):
```ts
function clone<T = any>(parent: T): T
```

Implementation changes:
1. **structuredClone fast-path** at entry: `if (typeof structuredClone === 'function') { try { return structuredClone(parent) } catch { /* fall through */ } }`. IE11 lacks structuredClone → skips. structuredClone throws on functions, DOM nodes, Symbols — caught → manual fallback (preserves 6.0.0 behavior where functions return the original reference).
2. **New branches** in manual clone: `Set` (new Set, recursively clone entries), `Map` (new Map, recursively clone keys+values), `ArrayBuffer.isView`/TypedArray (new `ctor(typedArray)`), `ArrayBuffer` (`slice(0)`).
3. **Iterative rewrite**: replace recursion with an explicit stack + `WeakMap` visited map (O(1) circular-ref lookup, replacing O(n) `parents.indexOf`). Preserves prototype handling. Eliminates deep-nesting stack overflow (verified by a 1000-deep test).
4. JSDoc updated: remove "Set, Map, Buffer, Promise are not supported" note; document structuredClone fast-path + fallback semantics.

### 4.B — Array/object

**`groupBy`** — extend `iteratee` to accept arrays (multi-field). Composite key joined by `separator` (default `'.'`).
```ts
function groupBy<T>(
  array: T[],
  iteratee:
    | keyof T
    | ((value: T) => string | number)
    | Array<keyof T | ((value: T) => string | number)>,
  options?: { separator?: string }
): Record<string, T[]>
```
Single-key call sites: behavior identical to 6.0.0 (no `options` → default separator unused for single keys).

**`unique`** — add optional `by`:
```ts
function unique<T = unknown>(arr: T[], by?: keyof T | ((item: T) => unknown)): T[]
```
No `by` → existing `indexOf` path (reference equality, unchanged). With `by` → `Map`-keyed dedup (first-wins). Objects without `by` keep 6.0.0 reference comparison.

**`sortBy`** (NEW, lodash `_.sortBy` analog) — note: current `sorter` is an `Intl.Collator` locale collator, **not** a field sort; overloading it would conflate semantics, so `sortBy` is a separate function.
```ts
type SortIteratee<T> =
  | keyof T
  | { field?: keyof T; order?: 'asc' | 'desc'; transform?: (v: unknown) => unknown }
function sortBy<T>(array: T[], ...iteratees: SortIteratee<T>[]): T[]
```
Returns a new sorted array (does not mutate). Multi-field tie-breaker semantics: iteratees applied left-to-right. Default order `'asc'`. Exported from array barrel + main index.

### 4.C — String

**`truncate`** — extend `TruncateOptions`:
```ts
interface TruncateOptions {
  length?: number        // default 30
  omission?: string     // default '...'
  separator?: string | RegExp
  byWidth?: boolean     // NEW: count CJK/full-width/emoji as width 2 (reuses isFullWidth from getCHSLength)
  breakEmoji?: boolean  // NEW: default true — don't split a grapheme cluster; IE11 uses surrogate-pair detection, modern env may use Intl.Segmenter when available
}
```
`byWidth: false` (default) → byte/char semantics identical to 6.0.0.

**`randomString`** — extend `RandomStringOptions`:
```ts
interface RandomStringOptions {
  charTypes?: RandomStringCharType | ArrayOneMore<RandomStringCharType>
  length?: number
  noConfuse?: boolean
  strict?: boolean
  secure?: boolean
  preset?: 'hex' | 'alphanum' | 'alpha' | 'numeric'  // NEW: overrides charTypes
  chars?: string                                       // NEW: overrides all char sets
}
```
Precedence when set: `chars` > `preset` > `charTypes`. Unset → 6.0.0 behavior. Presets map to fixed char sets (hex = `0-9a-f`, alphanum = `a-zA-Z0-9`, alpha = `a-zA-Z`, numeric = `0-9`). New `RandomStringPreset` type exported.

### 4.D — Date

**`formatDate`** — add 3rd optional param + new tokens:
```ts
interface FormatDateOptions {
  locale?: 'en' | 'zh'          // NEW: for locale-aware month/weekday names
  weekStartsOn?: 0 | 1 | 2 | 3 | 4 | 5 | 6  // NEW: affects week-of-year computation
}
function formatDate(date: DateInput, format = 'YYYY-MM-DD HH:mm:ss', options?: FormatDateOptions): string
```
New tokens (reuse existing `getWeekOfYear`/`getDayOfYear`/`getQuarter`):
- `Q` — quarter (1-4)
- `w` / `ww` — ISO-like week of year
- `DDD` — day of year
- `d` — weekday number (0-6)
- `dd` — weekday short name (locale table)
- `ddd` — weekday full name (locale table)
- `MMM` / `MMMM` — month short/full name (locale table)

Locale names provided via a hand-written table (en/zh) in `src/date/utils.ts`, consistent with existing `relativeTimeLocales` style — avoids `Intl.DateTimeFormat` for IE11 safety. Two-arg call sites: identical to 6.0.0.

**`parseDateWithFormat`** — harden existing (currently crude "simple extraction"): support `YYYY-MM-DD`, `YYYY/MM/DD`, `DD/MM/YYYY`, `YYYY年MM月DD日`, ISO-with-timezone. Replace bare-regex extraction with format-token-driven reverse parsing.

**`parseDate` / `parseDateWithFormat`** — export from `src/date/index.ts` barrel and from main `src/index.ts` Date section (currently internal-only).

## 5. Build & types pipeline

- `rolldown.config.ts`: `subpathEntries` += 5 entries. Build matrix unchanged (main = 4 bundles; subpaths = CJS+ESM each). IIFE/ES5 path for main untouched.
- `scripts/fix-types.mjs`: `subpathEntries` += 5 entries (auto mirror `.d.ts`).
- `package.json`: `exports` += 5 paths; `version` → `6.1.0`.
- `attw --pack --ignore-rules no-resolution` (`typecheck`) must pass for new subpaths.

## 6. Compatibility

- **IE11**: structuredClone feature-detected + fallback; truncate `breakEmoji` uses surrogate-pair detection (Intl.Segmenter optional, guarded); formatDate locale uses hand-written table; all syntax transpiled SWC→ES5 for IIFE.
- **Backward compat**: every change is "new optional param/option field" or "new export" — no narrowed signatures, no removals.
- Main `.` export surface for 6.0.0 consumers: identical (additive only).
