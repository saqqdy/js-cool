# js-cool 6.2.0 — Chain Subsystem Design Spec

- **Version**: 6.2.0 (minor)
- **Date**: 2026-08-13
- **Baseline**: 6.1.0 (assumed shipped; purely additive — chain depends on 6.1.0 `sortBy`/`unique`).
- **Direction**: New `chain` subsystem — lodash-style eager chained array operations. Fully backward-compatible, IE11 maintained, no breaking API changes.
- **Decomposition context**: 6.2.0 is the first of three deferred subsystems (6.2.0=chain, 6.3.0=schema, 6.4.0=plugin), sequenced by ascending risk.

## 1. Goals

1. Add a `chain` module: `chain(arr).filter(fn).sortBy('x').take(10).map(fn).value()` style eager chained array operations, reusing existing js-cool array functions + native `Array.prototype` methods.
2. Wire `./chain` additive-mirror subpath export (three-point: rolldown + fix-types + package.json `exports`); main `.` export gains `chain` only.
3. Zero behavior change for existing 6.0.0/6.1.0 call sites; IE11 IIFE build still passes SWC→ES5.

## 2. Non-goals (deferred)

- **Lazy evaluation / fusion**: deferred (eager reuses existing fns; lazy only pays off for large datasets outside js-cool's typical use).
- **Object chain** (`mapKeys`/`pick` chaining): deferred — cross-type dispatch adds complexity; array-only covers ~90% of use.
- **`_(...)` underscore alias**: YAGNI; `chain()` is the only entry.
- **`groupBy`/`partition` terminal variants**: these return non-array shapes (object / pair-array) that break the `Chain<T[]>` type; deferred to 6.3+ if needed.
- **schema** (6.3.0), **plugin** (6.4.0): separate specs.
- Coverage hard threshold (vitest has none; this release keeps it).

## 3. Architecture: eager evaluation model

- **Entry**: `chain<T>(value: T[]): Chain<T>` — the only construction path. `Chain<T>` constructor is not public (external code must go through `chain()`).
- **Internal state**: `private _value: T[]`. Each fluent method computes a new array (the underlying functions already return new arrays) and replaces `_value`; no mutation of the prior array.
- **Unwrap**: `.value()` returns `[...this._value]` (defensive copy) so callers cannot mutate the chain's internal state. Slight allocation cost accepted for footgun safety.
- **No generators / no `Symbol.iterator` / no `for...of`** in the implementation — internal loops use classic `for`/`Array.prototype` calls to stay IE11-clean without relying on SWC transpilation of modern syntax.

## 4. API surface

```ts
import { chain } from 'js-cool'          // or: import { chain } from 'js-cool/chain'

const result = chain([{n:3},{n:1},{n:2}])
  .filter(x => x.n > 0)
  .sortBy('n')
  .take(2)
  .map(x => x.n * 10)
  .value()                                   // => [10, 20]
```

## 5. Method set (12 fluent + 7 terminal)

### 5.1 Fluent (return `Chain<…>`, chain continues)

| method | backs onto | return type |
| --- | --- | --- |
| `map<U>(fn: (v: T, i: number) => U)` | native `Array.prototype.map` | `Chain<U>` |
| `filter(fn: (v: T, i: number) => boolean)` | native `Array.prototype.filter` | `Chain<T>` |
| `sortBy(...iteratees: SortIteratee<T>[])` | js-cool `sortBy` (6.1.0) | `Chain<T>` |
| `unique(by?: keyof T \| ((v: T) => unknown))` | js-cool `unique` (6.1.0) | `Chain<T>` |
| `chunk(size: number)` | js-cool `chunk` | `Chain<T>` |
| `take(n: number)` | js-cool `take` | `Chain<T>` |
| `drop(n: number)` | js-cool `drop` | `Chain<T>` |
| `flatten()` | js-cool `flatten` (single-level; no depth param — `flattenDeep` is a separate standalone fn) | `Chain<T>` |
| `reverse()` | native (non-mutating: `[...this._value].reverse()`) | `Chain<T>` |
| `slice(start?: number, end?: number)` | native `Array.prototype.slice` | `Chain<T>` |
| `concat(other: T[])` | native `Array.prototype.concat` | `Chain<T>` |
| `sampleSize(n: number)` | js-cool `sampleSize` (n random elements as array) | `Chain<T>` |

> Fluent methods that change element type (`map<U>`) return `Chain<U>`; all others return `Chain<T>`. No method in this set returns a non-array, so the chain type is always `Chain<…[]>`.

### 5.2 Terminal (return a plain value, chain ends)

| method | backs onto | return type |
| --- | --- | --- |
| `value()` | — | `T[]` (defensive copy) |
| `find(fn: (v: T, i: number) => boolean)` | native `Array.prototype.find` | `T \| undefined` |
| `reduce<U>(fn: (acc: U, v: T, i: number) => U, init: U)` | native `Array.prototype.reduce` | `U` |
| `some(fn: (v: T, i: number) => boolean)` | native `Array.prototype.some` | `boolean` |
| `every(fn: (v: T, i: number) => boolean)` | native `Array.prototype.every` | `boolean` |
| `includes(item: T)` | native `Array.prototype.includes` | `boolean` |
| `sample()` | js-cool `sample` (one random element) | `T \| undefined` |

## 6. Type design

```ts
import type { SortIteratee } from './sortBy'   // 6.1.0

export declare class Chain<T> {
	private constructor(arr: T[])
	map<U>(fn: (v: T, i: number) => U): Chain<U>
	filter(fn: (v: T, i: number) => boolean): Chain<T>
	sortBy(...iteratees: SortIteratee<T>[]): Chain<T>
	unique(by?: keyof T | ((v: T) => unknown)): Chain<T>
	chunk(size: number): Chain<T>
	take(n: number): Chain<T>
	drop(n: number): Chain<T>
	flatten(): Chain<T>
	reverse(): Chain<T>
	slice(start?: number, end?: number): Chain<T>
	concat(other: T[]): Chain<T>
	sampleSize(n: number): Chain<T>
	value(): T[]
	find(fn: (v: T, i: number) => boolean): T | undefined
	reduce<U>(fn: (acc: U, v: T, i: number) => U, init: U): U
	some(fn: (v: T, i: number) => boolean): boolean
	every(fn: (v: T, i: number) => boolean): boolean
	includes(item: T): boolean
	sample(): T | undefined
}

export function chain<T>(value: T[]): Chain<T>
export default chain
```

`SortIteratee<T>` is imported from 6.1.0's `src/sortBy.ts` (reused, not redefined — keeps the field/order/transform contract identical to standalone `sortBy`).

## 7. IE11 compatibility

- Native `map`/`filter`/`reduce`/`find`/`some`/`every`/`includes`/`slice`/`concat`/`reverse` are ES5 — IE11 supports them natively (no polyfill needed).
- js-cool backend functions (`sortBy`/`unique`/`chunk`/`take`/`drop`/`flatten`/`sample`) are transpiled SWC→ES5 in the IIFE bundle.
- No `Symbol.iterator`, no generator functions, no `for...of`, no spread in implementation internals (`reverse` uses `[...arr].reverse()` — the spread compiles to `arr.slice()` under SWC for ES5; verified at build).
- `[...this._value]` in `.value()` compiles to `this._value.slice()` — IE11-safe.

## 8. Subpath export (additive mirror)

Three-point wiring, consistent with the 6.0.0 `./ua`/`./binary` and 6.1.0 `./object`/`./array` pattern:
1. `rolldown.config.ts` → append `'chain/index'` to `subpathEntries`.
2. `scripts/fix-types.mjs` → append `'chain/index'` to `subpathEntries` (auto `.d.ts/.d.cts/.d.mts` mirror).
3. `package.json` `exports` → add `"./chain": { "import": "./dist/chain/index.mjs", "require": "./dist/chain/index.js" }`.

New barrel `src/chain/index.ts` re-exports `chain` (default + named) and `Chain` type from `../chain`. Main `src/index.ts` gains `export { default as chain, type Chain } from './chain'` in the Array section. Nothing removed from main `.` export.

## 9. Testing (TDD — tests before/with implementation)

`test/chain.test.ts`:
- Each fluent method: one input → `.value()` assertion.
- Type-flow: `map` changes `T→U` (e.g. `chain<number[]>(...).map(x => x.toString())` → `Chain<string>`).
- Terminal methods: `find`/`reduce`/`some`/`every`/`includes`/`sample` return scalars.
- Chained combination (the 4-step example in §4).
- Empty array: `chain([]).map(...).value()` → `[]`.
- `.value()` defensive copy: mutating the returned array does NOT affect a subsequent `.value()` call.
- `reverse` non-mutating: original input array unchanged after `chain(arr).reverse().value()`.
- `sortBy`/`unique` reuses 6.1.0 signatures (pass `SortIteratee` object, `by` option).

`test/subpath-exports.test.ts` (built in 6.1.0): add `./chain` import parity assertion.

No coverage threshold added. Target: maintain 90%+ on `src/chain.ts`.
