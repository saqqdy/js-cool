# js-cool 6.2.0 — Chain 子系统设计规范

- **版本**：6.2.0（minor）
- **日期**：2026-08-13
- **基线**：6.1.0（假定已发布；纯附加——chain 依赖 6.1.0 的 `sortBy`/`unique`）。
- **方向**：新增 `chain` 子系统——lodash 风格的急求值链式数组操作，复用既有 js-cool 数组函数 + 原生 `Array.prototype` 方法。完全向后兼容，保持 IE11，无破坏性 API 变更。
- **分解上下文**：6.2.0 是三个延迟子系统的第一个（6.2.0=chain、6.3.0=schema、6.4.0=plugin），按风险递增排序。

## 1. 目标

1. 新增 `chain` 模块：`chain(arr).filter(fn).sortBy('x').take(10).map(fn).value()` 风格的急求值链式数组操作，复用既有 js-cool 数组函数 + 原生 `Array.prototype` 方法。
2. 接线 `./chain` 附加镜像子路径导出（三点：rolldown + fix-types + package.json `exports`）；主 `.` 导出仅新增 `chain`。
3. 对现有 6.0.0/6.1.0 调用方零行为变更；IE11 IIFE 构建仍通过 SWC→ES5。

## 2. 非目标（延迟）

- **惰性求值 / fusion**：延迟（急求值复用既有函数；惰性仅对大数据集有意义，超出 js-cool 典型用途）。
- **对象 chain**（`mapKeys`/`pick` 链式）：延迟——跨类型派发增加复杂度；仅数组覆盖约 90% 用途。
- **`_(...)` 下划线别名**：YAGNI；`chain()` 是唯一入口。
- **`groupBy`/`partition` 终端变体**：这些返回非数组形状（对象 / pair-array），会破坏 `Chain<T[]>` 类型；延迟到 6.3+ 如需。
- **schema**（6.3.0）、**plugin**（6.4.0）：独立规范。
- 覆盖率硬阈值（vitest 无；本版本保持）。

## 3. 架构：急求值模型

- **入口**：`chain<T>(value: T[]): Chain<T>`——唯一构造路径。`Chain<T>` 构造函数非 public（外部代码必须经 `chain()`）。
- **内部状态**：`private _value: T[]`。每个 fluent 方法计算一个新数组（底层函数已返回新数组）并替换 `_value`；不修改前一个数组。
- **解包**：`.value()` 返回 `[...this._value]`（防御性拷贝），使调用方无法修改链的内部状态。为避免 footgun 接受轻微分配开销。
- **无 generators / 无 `Symbol.iterator` / 无 `for...of`**——内部循环用经典 `for`/`Array.prototype` 调用，保持 IE11 清洁，不依赖 SWC 对现代语法的转译。

## 4. API 表面

```ts
import { chain } from 'js-cool'          // 或: import { chain } from 'js-cool/chain'

const result = chain([{n:3},{n:1},{n:2}])
  .filter(x => x.n > 0)
  .sortBy('n')
  .take(2)
  .map(x => x.n * 10)
  .value()                                   // => [10, 20]
```

## 5. 方法集（12 fluent + 7 terminal）

### 5.1 Fluent（返回 `Chain<…>`，链继续）

| 方法 | 后端 | 返回类型 |
| --- | --- | --- |
| `map<U>(fn: (v: T, i: number) => U)` | 原生 `Array.prototype.map` | `Chain<U>` |
| `filter(fn: (v: T, i: number) => boolean)` | 原生 `Array.prototype.filter` | `Chain<T>` |
| `sortBy(...iteratees: SortIteratee<T>[])` | js-cool `sortBy`（6.1.0） | `Chain<T>` |
| `unique(by?: keyof T \| ((v: T) => unknown))` | js-cool `unique`（6.1.0） | `Chain<T>` |
| `chunk(size: number)` | js-cool `chunk` | `Chain<T>` |
| `take(n: number)` | js-cool `take` | `Chain<T>` |
| `drop(n: number)` | js-cool `drop` | `Chain<T>` |
| `flatten()` | js-cool `flatten`（单层；无 depth 参数——`flattenDeep` 是独立函数） | `Chain<T>` |
| `reverse()` | 原生（非修改：`[...this._value].reverse()`） | `Chain<T>` |
| `slice(start?: number, end?: number)` | 原生 `Array.prototype.slice` | `Chain<T>` |
| `concat(other: T[])` | 原生 `Array.prototype.concat` | `Chain<T>` |
| `sampleSize(n: number)` | js-cool `sampleSize`（n 个随机元素组成的数组） | `Chain<T>` |

> 改变元素类型的 fluent 方法（`map<U>`）返回 `Chain<U>`；其余均返回 `Chain<T>`。本集合中无方法返回非数组，故链类型始终为 `Chain<…[]>`。

### 5.2 Terminal（返回纯值，链结束）

| 方法 | 后端 | 返回类型 |
| --- | --- | --- |
| `value()` | — | `T[]`（防御性拷贝） |
| `find(fn: (v: T, i: number) => boolean)` | 原生 `Array.prototype.find` | `T \| undefined` |
| `reduce<U>(fn: (acc: U, v: T, i: number) => U, init: U)` | 原生 `Array.prototype.reduce` | `U` |
| `some(fn: (v: T, i: number) => boolean)` | 原生 `Array.prototype.some` | `boolean` |
| `every(fn: (v: T, i: number) => boolean)` | 原生 `Array.prototype.every` | `boolean` |
| `includes(item: T)` | 原生 `Array.prototype.includes` | `boolean` |
| `sample()` | js-cool `sample`（一个随机元素） | `T \| undefined` |

## 6. 类型设计

```ts
import type { SortIteratee } from './sortBy'   // 6.1.0

export declare class Chain<T> {
	private constructor(arr: T[])
	map<U>(fn: (v: T, i: number) => U): Chain<U>
	filter(fn: (v: T, i: number) => boolean): Chain<T>
	sortBy(...iteratees: SortIteratee<T>[]): Chain<T>
	unique(by?: keyof T | ((v: T) => unknown)): Chain<T>
	chunk(size: number): Chain<T>
	take(n: number): Chain<T>
	drop(n: number): Chain<T>
	flatten(): Chain<T>
	reverse(): Chain<T>
	slice(start?: number, end?: number): Chain<T>
	concat(other: T[]): Chain<T>
	sampleSize(n: number): Chain<T>
	value(): T[]
	find(fn: (v: T, i: number) => boolean): T | undefined
	reduce<U>(fn: (acc: U, v: T, i: number) => U, init: U): U
	some(fn: (v: T, i: number) => boolean): boolean
	every(fn: (v: T, i: number) => boolean): boolean
	includes(item: T): boolean
	sample(): T | undefined
}

export function chain<T>(value: T[]): Chain<T>
export default chain
```

`SortIteratee<T>` 从 6.1.0 的 `src/sortBy.ts` 导入（复用，不重定义——保持与独立 `sortBy` 相同的 field/order/transform 契约）。

## 7. IE11 兼容性

- 原生 `map`/`filter`/`reduce`/`find`/`some`/`every`/`includes`/`slice`/`concat`/`reverse` 为 ES5——IE11 原生支持（无需 polyfill）。
- js-cool 后端函数（`sortBy`/`unique`/`chunk`/`take`/`drop`/`flatten`/`sample`）在 IIFE bundle 中经 SWC→ES5 转译。
- 无 `Symbol.iterator`、无 generator 函数、无 `for...of`，实现内部无 spread（`reverse` 用 `[...arr].reverse()`——spread 在 SWC 下编译为 `arr.slice()` 以兼容 ES5；构建时验证）。
- `.value()` 中的 `[...this._value]` 编译为 `this._value.slice()`——IE11 安全。

## 8. 子路径导出（附加镜像）

三点接线，与 6.0.0 `./ua`/`./binary` 及 6.1.0 `./object`/`./array` 模式一致：
1. `rolldown.config.ts` → 在 `subpathEntries` 追加 `'chain/index'`。
2. `scripts/fix-types.mjs` → 在 `subpathEntries` 追加 `'chain/index'`（自动 `.d.ts/.d.cts/.d.mts` 镜像）。
3. `package.json` `exports` → 添加 `"./chain": { "import": "./dist/chain/index.mjs", "require": "./dist/chain/index.js" }`。

新 barrel `src/chain/index.ts` 从 `../chain` 重新导出 `chain`（default + named）及 `Chain` 类型。主 `src/index.ts` 在 Array 节新增 `export { default as chain, type Chain } from './chain'`。不从主 `.` 导出删除任何内容。
